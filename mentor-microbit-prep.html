Set up and rehearse each laptop.

  1. Open the starter below. Make a local copy with a recognizable class name; keep the three button events. No extension is required.
  2. Run all three simulator checks. A shows a heart, B a happy face, A+B clears the display. Starting or resetting begins with a blank display.
  3. Transfer to the matched W board. Test the actual cable/port. Download a compiled .hex backup from MakeCode before Thursday and store it with the project.
  4. Test battery operation. Wait until transfer flashing finishes, unplug USB, attach the 2×AAA holder, and repeat all three buttons plus reset. This physical check must be done on each released kit.

Starter code: blocks and text.

Use A → heart · B → happy face · A+B → clear. The initial clear-screen block also gives a predictable restart. Students change one icon and test again.

Review or copy the text.

In a new MakeCode project, choose JavaScript, replace the existing code with this starter, then choose Blocks. The .ts download is source text; use MakeCode’s Download button to produce the .hex for a physical board.

input.onButtonPressed(Button.A, function () {
    basic.showIcon(IconNames.Heart)
})
input.onButtonPressed(Button.B, function () {
    basic.showIcon(IconNames.Happy)
})
input.onButtonPressed(Button.AB, function () {
    basic.clearScreen()
})
basic.clearScreen()

Transfer, wait, then physically test.

  1. Connect. Keep the battery holder disconnected. Plug the W board into its laptop with the data cable; look for the MICROBIT drive.
  2. Download. In supported Chrome/Edge setups, follow MakeCode’s Connect device/pairing prompts to transfer directly. If direct transfer is unavailable, save the compiled .hex and copy it to the MICROBIT drive using File Explorer.
  3. Wait. Leave the cable attached until the activity light finishes flashing. MakeCode’s simulator working does not prove the physical transfer succeeded.
  4. Test. Unplug USB, connect the correct holder, and test A, B, and A+B. Press the back reset button once; the screen should clear and the button behaviors remain available.

SymptomNext check
No MICROBIT driveReseat the data cable; try the tested spare cable or another laptop port.
Simulator changes, physical board does notRepeat the transfer to the matched kit; verify the compiled .hex reached MICROBIT.
Transfer still flashingWait; do not unplug. Get the technical lead if it continues unusually long.
Works on USB onlyAfter disconnecting USB, check holder plug, cell direction, and fresh matched cells.
Robotics initials or the wrong boardStop and return it to Tri. Do not overwrite BirdBrain firmware or swap pools.
Internet unavailableUse the previously opened editor/offline backup; demonstrate on the preloaded board and record what students actually tested.
