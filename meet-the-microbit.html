Our actual workflow

Stauffer has 40 micro:bit V2 boards with battery holders and USB cables. Wearable micro:bits are programmed on classroom Windows laptops. Mentors may preload the starter program before the workday.

See the program supply guide →
If your board is already programmed: Test A, B, and A+B first. Then open the matching starter project on a laptop, change one icon, test it in the simulator, and transfer the revision when your station is ready.
Keep the pathways separate: Wearable micro:bits use MakeCode. Robotics micro:bits inside the Hummingbird kits use BirdBrain firmware for the BirdBlox iPad app. Never swap an unlabeled board between pathways.

Build

Create your first MakeCode program

  1. Match the labels.

    Confirm that the micro:bit, USB cable, battery holder, and storage bag have the same wearable kit number.

  2. Connect by USB.

    Plug the micro:bit into a classroom Windows laptop with the kit’s USB data cable. Leave the battery holder disconnected while USB is connected.

  3. Open MakeCode.

    Go to makecode.microbit.org, choose New Project, and name it with your first name plus “First microbit.”

  4. Program Button A.

    From Input, add an on button A pressed block. Place a show icon heart block inside it.

  5. Program Button B.

    Add another button event, change its dropdown to B, and show a happy face.

  6. Program A+B.

    Add a third button event, change it to A+B, and place clear screen inside it.

  7. Test the simulator.

    Press A, B, and A+B on the on-screen micro:bit. Fix the code before transferring it.

  8. Download to the board.

    Select Download and follow MakeCode’s Windows instructions. Your laptop may pair directly or ask you to save/copy the program to the MICROBIT drive.

  9. Wait, then disconnect.

    Wait until the transfer/activity light finishes flashing. Unplug the USB cable, then connect the 2×AAA holder.

  10. Run the physical test.

    Press A, B, and A+B on the real board. Press the reset button on the back once to restart the current program.

Test

Your program passes when…

  • Button A shows a heart.
  • Button B shows a happy face.
  • A+B clears the screen.
  • The same behavior works in the simulator and on the physical micro:bit.
  • The board restarts correctly when you press reset once.
  • You can explain which parts are inputs and which part is the output.

Troubleshoot

If the program will not run

STOP→OBSERVE→CHANGE ONE THING→TEST

No MICROBIT drive

Reconnect both ends of the USB cable. Try the kit’s known-good data cable or another laptop port.

Works only in simulator

The code has not reached the board. Select Download and complete the transfer step.

Old program still runs

Check that you downloaded to the micro:bit with your matching kit number—not a neighbor’s board.

No battery power

Check the holder plug and battery direction. Ask a mentor for fresh batteries; do not mix old and new cells.

Transfer light still flashes

Wait. Do not unplug during transfer. Ask a mentor if flashing continues unusually long.

Wrong pathway firmware

If the board shows robotics connection initials or behaves unexpectedly, stop and give it to a mentor. Do not move robotics boards into wearable kits.

How this connects to your bucket hat

Your final hat program will keep the same event structure: Button A will run your signature color/effect, Button B will run a second animation, and A+B will turn the NeoPixels off. The next tutorial introduces the pixels.
